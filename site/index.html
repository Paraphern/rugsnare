Three commands to protection.

Works with Claude Code, Cursor, Windsurf, VS Code, Continue, Zed, Cline, ZCode, and any MCP-compatible client.

1
PIN

Pin your current servers

$ npx rugsnare scan
  pinned github: 12 tool(s) -> search_code, create_issue, ...
  pinned filesystem: 14 tool(s) -> read_file, write_file, ...
  ✅ Pinned. Commit .rugsnare/pins.json to your repo.

Auto-discovers your MCP configs, pins every tool contract, and signs the baseline with Ed25519.

2
GATE

Gate your CI

$ npx --yes rugsnare@1.1.0 diff --config .mcp.json
github  (npx -y @modelcontextprotocol/server-github)
  [ok ] create_issue
  [ok ] search_code
rugsnare diff: clean
# exit 0 — but if anything changed after approval:
# [DRIFT] search_code (BREAKING) → exit 1, build fails

One line in CI. Any tool contract that changed since your last review fails the build. BREAKING vs COSMETIC split, SARIF output for code scanning. Pin the version — rugsnare's own floating-version check flags unpinned npx launches, so CI examples pin it too; rugsnare doctor --check-update tells you when a newer release exists.

Scan chat exports, notes, and .env files for leaked secrets: API keys, private keys, Luhn-valid cards, BIP-39 seed phrases. Redacted output (first 4 chars), --airgap leaves no trace. Exit 1 = HIGH findings.

Your AI's instructions changed. Nobody told you.

Skill files (SKILL.md, .mdc, rules) are instructions your AI agent follows. They can be silently modified by a teammate, a marketplace update, or a compromised repo. RugSnare catches it.

$ rugsnare skills scan
  Pinned 23 skill file(s) across 5 platform(s).
$ rugsnare skills report
  Report: .rugsnare/skills-report.html
  1 dangerous, 2 review, 20 unchanged

One command generates a visual report in your browser. See exactly what changed, why it's dangerous, and what to do.

Eight mechanisms, one job: nothing changes unnoticed.

Each mechanism catches what the previous one cannot see.

Hash pinning, contracts includedTools, prompts, and resources pinned by sha-256. Split hash: BREAKING (schema) vs COSMETIC (description). Ed25519-signed baseline, verifiable in CI.
Live proxy, stdio + HTTPSits between client and server on both transports. Observes traffic, then quarantines mid-session swaps in enforce mode. Chameleon detection catches per-client contract switching.
Result inspectionEvery tool response scanned for injection indicators: instruction overrides, exfiltration URLs, "don't tell the user", invisible Unicode. Advisory-only, never blocks data.
Canary record + replayRecord real tool calls, replay them against a new server version before upgrading. Read-only calls replay freely; write-class needs explicit opt-in. Deterministic verdicts.
Call policies + budgetsYAML/JSON policies: deny session:object, PII egress checks, dangerous-shell detection. Per-tool session budgets and an operator kill-switch.
Secret vaultThe model sends {{VAULT:NAME}} placeholders; the proxy injects real values to the server and scrubs them from results. Logging and traces see placeholders only.
Cross-server shadow detectionCatches the same tool name in different servers, where the client's resolution order silently decides which implementation runs.
18 advisory signals, first contactReads descriptions on first contact: "do not tell the user", credential paths, base64 exfiltration, ANSI escapes, phone numbers. No baseline needed.
