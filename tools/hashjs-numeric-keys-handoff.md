# Handoff: hash.js - integer-like property keys break JCS lexicographic ordering

**Дата:** 2026-10-29 · Источник: kimjooyoon в [issue #6](https://github.com/Paraphern/rugsnare/issues/6) (коммент 27.10 19:12), подтверждено исследовательским чатом живым прогоном.

## Баг

`stable()` в `product/src/hash.js` сортирует ключи лексикографически, **но складывает результат в обычный JS-объект** (`out[key] = ...`). По ECMAScript-спеке (OrdinaryOwnPropertyKeys) integer-подобные строковые ключи (`"2"`, `"10"`) перечисляются в возрастающем **числовом** порядке независимо от порядка вставки. `JSON.stringify(stable(x))` для таких ключей emits числовой порядок - сортировка молча отменяется.

JCS §3.2.3 требует лексикографический порядок (`"10"` < `"2"`). PIN-SPEC заявляет лексикографический профиль => это баг против собственной спеки.

## Воспроизведение (проверено)

```js
const tool = { name: 'lookup', description: '', inputSchema: { type: 'object',
  properties: { '10': { type: 'string' }, '2': { type: 'integer' } } } };
// Object.keys(stable(tool).inputSchema.properties) => ["2","10"]  (числовой порядок!)
// surfaceHash([tool]) => a40da8451aa76046b5e5f15761ed06a1ae4aaf5df50174ab7fa46813c22ae4a5
// алфавитный контроль => порядок верный (["aa","ab"])
```

## Фикс (форма)

Канонический сериализатор, который **эмитит ключи из отсортированного списка напрямую**, без материализации промежуточного объекта - JS-объект принципиально не может нести нужный порядок для этого класса ключей. Т.е. `serialize(value)`: рекурсивно, для объектов - `Object.keys(value).sort()` и ручная склейка `'"'+key+'":'+serialize(v)`, для массивов - по индексу, для строк/чисел - JSON-правила (JCS §3.2.2.3 для чисел).

## Совместимость

Хирургическая: дайджесты меняются **только** для схем с integer-подобными именами свойств. Все прочие пины хэшируются идентично - существующий корпус не дрейфует, если в его схемах нет таких ключей. Требуется свип корпуса на этот класс (`grep '"[0-9]+":'` по inputSchema в pins/) до релиза фикса.
