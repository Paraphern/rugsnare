# GitHub outreach: правила и чек-листы (уроки 2026-10-07)

## Чек-лист перед ЛЮБЫМ постом в чужом issue/discussion (обязателен)

1. **Статус темы**: `gh issue view <n> --repo <r> --json state,stateReason,closedAt`.
   - `state: closed` → НЕ постить. Исключение: осознанное решение (см. ниже).
   - `stateReason: completed` + дата закрытия ДО нашего события → тема мертва, искать живую.
2. **Куда мигрировала дискуссия**: закрытые issue часто ссылаются на дубль/PR/discussion - проверить тело перед уходом.
3. **Discussions включены?** `gh api repos/<r> --jq .has_discussions` - для исследовательского контента (карты, отчёты) discussion лучше issue: не закрываются, не являются баг-треком.
4. **Свежесть**: `updatedAt` за последние ~2 недель → тема живая; год молчания → аудитория ушла.
5. **Реакция на наш прошлый контент в этом репо**: если 0 реакций и 0 ответов на прошлый комментарий - не долбить тот же канал.

## Правила серии

- **Один репозиторий в день** максимум для исходящего контента.
- **Вклад first, инструмент last**: находка/карта/репро - в начале; rugsnare - в хвосте, как «чем поймал».
- **Никогда не постить одно и то же в несколько мест подряд** (урок Reddit-фильтров - тот же паттерн детектится и людьми).
